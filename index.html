Learn

Learn SQL with logical execution

Conventional SQL teaching often describes the conceptual order as FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. SQLFlow's displayed stages follow its actual executor: FROM → JOIN → WHERE → GROUP BY → SELECT / AGGREGATE → HAVING → DISTINCT → ORDER BY → LIMIT. Only stages used by a query appear. SQLFlow calculates grouped projections before filtering those groups with HAVING; the final rows still reflect the HAVING condition.

Interactive SQLFlow Manual

Quick-start checklist
  1. Choose a built-in table or create/import custom data.
  2. Write SQL or select a built-in example.
  3. Run the query with Run Query or Ctrl/Cmd + Enter.
  4. Inspect stages with Previous, Next, or Auto Play.
  5. Open Explanation, Relational Algebra, or Query Tree.
  6. Download the execution report.

Supported input

Enter one supported statement at a time: SELECT, INSERT, UPDATE, DELETE, BEGIN, COMMIT, ROLLBACK, SAVEPOINT, or ROLLBACK TO. SELECT supports FROM, INNER/LEFT JOIN with equality ON, WHERE with comparisons and AND/OR/parentheses, GROUP BY, HAVING, DISTINCT, ORDER BY, LIMIT, and COUNT/SUM/AVG/MIN/MAX. Data changes apply to custom tables.

Current limits

SQLFlow does not implement subqueries, CTEs, window functions, RIGHT/FULL OUTER JOIN, physical plans, index simulation, cost-based optimization, backend connections, or concurrency/locking.

Input and examples

SQLFlow accepts supported SELECT, DML, and transaction statements. Pick an example, edit it in the SQL editor, then run one statement at a time.

Execution navigation

Previous and Next select intermediate datasets. Auto Play advances automatically. Final Result shows the completed output.

Reading visualizations

Execution tables show rows after each operation. JOIN view highlights compared keys. Algebra summarizes operators, Query Tree shows the logical plan, and Explanation narrates measured results.

Transactions

BEGIN opens a working copy; COMMIT persists it; ROLLBACK discards it. SAVEPOINT and ROLLBACK TO manage checkpoints.

Custom data and reset

Create typed tables or import CSV in Database Explorer. Reset Demo restores the default query and preserves custom tables unless Clear Custom Data is explicitly confirmed.

Presentation and reports

Presentation Mode emphasizes teaching views. Open Execution Report shows the report with separate Download TXT Report and Print / Save as PDF actions.

Keyboard shortcuts

Ctrl/Cmd+Enter runs SQL, Alt+Right/Left changes stage, and Escape closes an open panel or Presentation Mode.

Project overview

Problem Statement
Students can execute SQL queries but often cannot see how rows change through each logical operation.
Objective
Build an interactive browser-based system that visualizes SQL execution step-by-step and connects SQL syntax with relational operations and intermediate results.
Area
Core Database Systems / Database Management Systems
Activity Type
Innovation Sprint / Working Prototype

System architecture

SQL Input↓Parser↓Parsed AST↓Execution Engine↓Stages + Metadata↓Visualization / Educational Output Layer↓Final Result / Explanation / Relational Algebra / Query Tree / Execution Report

Module design

Interactive learning modules

simulation.js replays executor instrumentation; help.js controls the searchable manual and guided tutorials; quiz-bank.js contains authored questions and isolated fixtures; quiz-engine.js handles grading and persistence; quiz.js renders attempts and reviews.

Working methodology

  1. The user enters one supported SQL statement.
  2. The token-aware parser validates syntax and creates a structured AST.
  3. The executor reads SQLFlow's in-browser tables and records rows, columns, and operation metadata at each supported logical stage.
  4. The visualizer shows intermediate relations and measured row-count changes.
  5. The same structured result feeds Final Result, deterministic Explanation, and the downloadable execution report. SELECT queries also produce relational algebra and a logical query tree.
  6. INSERT, UPDATE, DELETE, and transaction controls use the working-copy and snapshot mechanism for pending changes, savepoints, commit, and rollback.

Testing and reliability

SQLFlow Version 1.4 passed 1,497 browser regressions and 412 complete Chrome interaction checks before release. Coverage includes the SQL engine, transactions, reports, safe rendering, quiz fixture keys and grading, action replay, state cleanup, and learning navigation. The dependency-free Chrome suite exercises actual buttons, tutorials, downloads, and responsive dialogs.

Creative features

Intermediate datasets, JOIN comparison highlighting, synchronized query trees, deterministic English explanations, relational algebra, custom tables and CSV, transaction snapshots and savepoints, Presentation Mode, keyboard navigation, and extensive browser testing extend SQLFlow beyond a basic query executor.

Challenges and solutions

  • A token-aware parser handles supported SQL without a backend dependency.
  • Qualified row provenance preserves aliases and JOIN correctness.
  • Immutable stage metadata synchronizes tables, trees, algebra, explanations, and reports.
  • Transaction snapshots make rollback and savepoints deterministic.
  • Safe DOM APIs prevent table values and SQL text from becoming executable HTML.

Future enhancements

Subqueries, CTEs, window functions, RIGHT/FULL JOIN, physical plans, index simulation, cost estimation, backend connections, richer exports, and drag/zoom trees remain future work.

Conclusion

SQLFlow demonstrates how SQL statements transform data through logical stages, helping bridge the gap between SQL syntax and internal database operations.
